# Retro Pipeline — Pointers

The retro pipeline (Godot → `.glb`/`.pbm` → PSP/raylib viewers) has its own
deep docs. Read the relevant one; do not duplicate them here.

| Topic | Doc |
|---|---|
| Authoring levels, export dialog knobs, what the export bakes, pitfalls | `retro_engine/RETRO-AUTHORING.md` |
| Real-PSP measurement: PSPLink over USB, the `./run_psp_hw.sh` loop, the hard-reset rule, why PPSSPP/desktop numbers are not evidence | `retro_engine/psp/HARDWARE-TESTING.md` |
| The engine's optimization inventory with measured cost of every decision (fill, texture-cache cliff, mip/LOD policy, per-frame budget) | `retro_engine/psp/OPTIMIZATION.md` |
| The `.pbm` byte format + consumer performance rules | `SPEC_RETRO_FORMAT.md` |
| Parity oracle for the `.pbm` writer | `retro_engine/pbm_conv.py` (the GDScript `export/pb_pbm_converter.gd` must stay byte-compatible) |

Non-negotiables (details in the docs above):
1. A performance number is real only if it came from a PSP over USB
   (`./run_psp_hw.sh`). Emulators and desktop viewers are correctness-only.
2. Changed a measured default (LOD bias, filter, texture format, emitter
   budget)? Re-measure and update the row in the same commit.
3. Map-format changes require re-testing the raylib engine too, not just
   the PSP one.
4. Build artifacts (`EBOOT.PBP`, `*.prx`, `PoiRetro_PSP.zip`, exports) are
   gitignored and regenerated by `./run_psp.sh` / `./run_tests.sh` /
   `./showcase_map.sh` — never commit them.
